# Файловый агент (create / edit / delete в рабочей папке)

CodeSentry умеет не только анализировать код, но и напрямую работать
с файлами в заранее заданной рабочей папке — создавать, редактировать,
дописывать и удалять файлы по задаче на естественном языке. Всё через
локальную Ollama, полностью офлайн.

## Возможности на данный момент

| Возможность | Инструмент / эндпоинт | Комментарий |
|---|---|---|
| Прочитать файл | `read_file` / `GET` через `read_file` | Текстовые файлы |
| Создать / перезаписать файл | `write_file` | |
| Дописать в конец файла | `append_file` | |
| Удалить файл | `delete_file` | Только файлы, не папки |
| Создать папку | `create_directory` | |
| Список файлов в одной папке | `list_files` | Нерекурсивно |
| **Полный список файлов во всех подпапках** | `list_files_recursive` / `GET /api/agent/tree` | Рекурсивно, с фильтром служебных папок (`.git`, `__pycache__` и т.д.) |
| **Поиск по названию файла/папки** | `search_files_by_name` / `GET /api/agent/search/name?pattern=...` | Регистронезависимая подстрока, рекурсивно по всей рабочей папке |
| **Поиск по содержимому файлов** | `search_file_content` / `GET /api/agent/search/content?query=...` | Регистронезависимо, возвращает файл + номер строки + фрагмент, только для текстовых расширений, файлы больше 2 МБ пропускаются |
| **Объяснение файла простым языком** | `explain_file` / `GET /api/agent/explain/file?relative_path=...` | Через локальную LLM: читает файл и описывает назначение, а не пересказывает код построчно |
| **Обзор всей папки простым языком** | `explain_folder` / `GET /api/agent/explain/folder` | Смотрит на список файлов и структуру, описывает, что это за проект/набор данных |

Все перечисленные инструменты доступны и напрямую через REST (быстрее,
предсказуемый ответ), и через диалоговый агентский режим `POST /api/agent/run`
(модель сама решает, какие из них вызвать по свободной формулировке задачи).

## Как это работает

1. Пользователь формулирует задачу: *"создай файл plan.md с планом
   рефакторинга модуля payment"*.
2. Локальная модель (через `/api/chat` Ollama с function calling)
   решает, какой инструмент вызвать: `list_files`, `read_file`,
   `write_file`, `append_file`, `delete_file`, `create_directory`.
3. Инструмент реально выполняется в `apps/agent_tools/file_tools.py`
   и результат возвращается модели — цикл повторяется, пока задача
   не будет выполнена (`apps/agent_tools/agent.py`).

## Песочница — самое важное

Агент **физически не может** выйти за пределы папки, заданной в
`.env` как `AGENT_WORKSPACE_DIR` (например, `D:\AI`). Любой путь
проверяется в `file_tools._resolve_safe_path`: если после разрешения
`..`/абсолютных путей результат не находится внутри этой папки —
операция отклоняется с `UnsafePathError`, файл не читается,
не создаётся и не удаляется.

Это защита от:
- случайной команды пользователя, которая по ошибке указывает путь наружу;
- некорректного/непредсказуемого ответа модели (галлюцинации в путях);
- потенциально вредоносного промпт-инъекшена, если задача когда-либо
  будет приходить не напрямую от пользователя (например, из внешнего файла).

**Перед использованием**: настройте `AGENT_WORKSPACE_DIR` на папку,
специально выделенную под работу агента, не на системные каталоги
и не на корень диска.

## Как запустить

Через веб-API:
```
POST /api/agent/run
{ "task": "создай файл notes.txt с планом на неделю" }
```

Через терминал:
```
poetry run python scripts/run_agent.py "создай файл notes.txt с планом на неделю"
```

## Ограничения текущей реализации

- Удаление и редактирование **только файлов**, не папок целиком
  (осознанное ограничение, чтобы случайно не снести директорию).
- Требуется модель Ollama с поддержкой tools/function calling
  (проверено на семействе `qwen2.5-coder` и `llama3.1+`).
- Лимит шагов агента (`MAX_STEPS = 8`) — защита от зацикливания.

## Кто в команде отвечает
